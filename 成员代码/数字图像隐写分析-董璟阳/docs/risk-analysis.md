# 风险分析记录

## 选定模块

图像信息隐藏模块：`成员代码/数字图像隐写分析-董璟阳/`

本次 PR 负责对图像信息隐藏模块进行安全加固与功能完善，在保留原有图像预处理、LSB 信息嵌入、信息提取、位平面分析和 DCT 分析功能的基础上，重点增强输入合法性校验、文件安全检查、异常处理以及日志记录等安全控制措施，提高程序的可靠性和安全性。

## 涉及的敏感操作

* 用户输入秘密信息，并转换为二进制数据进行嵌入。
* 读取用户指定的图像文件并进行灰度化、缩放等预处理。
* 修改图像 RGB 像素最低有效位（LSB），生成隐写图像。
* 从隐写图像中提取隐藏信息并恢复原始内容。
* 本地文件读写，包括原始图像、隐写图像及实验结果输出。
* 图像质量分析，包括 PSNR 计算、位平面分析及 DCT 频域处理。

## 主要安全风险

1. 输入数据缺乏合法性校验风险

   当前程序未对秘密信息的长度、数据类型及编码格式进行检查，用户可以输入超长字符串或非法数据，可能导致程序运行异常、资源占用过高，甚至超过图像可嵌入容量，造成隐藏失败或程序崩溃。

2. 图像容量不足导致数据完整性风险

   程序在嵌入信息前未检测图像可用容量，当秘密信息超过图像实际可隐藏容量时，程序仍继续写入，可能导致数据被截断、提取失败或恢复结果乱码，影响隐藏信息的完整性。

3. 文件访问与格式校验不足风险

   程序默认输入图像存在且格式正确，对于不存在、损坏或非图像格式文件缺少统一校验与异常处理，容易导致程序直接抛出异常退出，降低系统稳定性。

4. 信息提取依赖人工指定长度风险

   当前提取函数需要用户提供秘密信息长度，若长度输入错误，将导致恢复内容错误或乱码。同时，该方式也降低了程序的易用性，不利于后续扩展和自动化处理。

5. 缺少异常处理与日志审计风险

   程序主要通过 `print()` 输出运行信息，没有建立统一的异常处理机制和日志记录功能。当程序发生错误时，无法准确定位问题原因，也缺乏必要的运行审计记录，不符合安全开发规范。

## 安全目标

* 增加输入合法性检查，对秘密信息长度、数据类型和编码格式进行校验。
* 在信息嵌入前检测图像容量，容量不足时及时终止操作并返回明确提示。
* 对输入图像路径、文件格式及读取过程增加合法性验证和异常处理，避免程序因非法文件崩溃。
* 优化信息提取流程，增加结束标识或自动识别机制，减少对人工输入消息长度的依赖，提高提取准确性。
* 完善异常处理和日志记录功能，对关键操作及异常信息进行统一记录，提升程序可维护性和安全审计能力。
